# ADR-003: CV PDF via headless Chrome, with a Pandoc fallback

Status: accepted
Date: 2026-10-19

## Context

The CV page must be downloadable as a PDF that matches the published page. Doing
that by hand is how stale PDFs end up attached to inboxes, so the PDF has to be
generated by CI from the same build that is deployed.

## Decision

Render `content/cv/index.html` with **Chrome for Testing**, pinned by version
(`CHROME_VERSION: 155.0.8059.84`, downloaded from
`chrome-for-testing-public`, unpacked to `.chrome/`) rather than the runner's
apt Chromium, so the artifact does not change because the runner image changed.

Two details are load-bearing:

1. **The build is served over `127.0.0.1`, not opened as `file://`.** The site is
   deployed under a sub-path (`baseURL = https://sternnick.github.io/nster/`), so
   its asset URLs are absolute paths like `/nster/assets/…`. Under `file://` those
   resolve to the filesystem root and the PDF prints unstyled.
2. **`--virtual-time-budget=8000`** lets font and asset loading finish before the
   print, and `--no-pdf-header-footer` keeps Chrome's date/URL chrome off the page.

The step is followed by a text audit (`pypdf`): no phone-shaped numbers, no
address other than `you@example.com`, and the literal string `Sample` present —
i.e. the PDF is checked as an artifact, not just assumed to be the page.

## Consequences

- The PDF is inside `public/`, so it is also **published** as `/nster/cv.pdf` by
  the deploy job. Sample-only content is what makes that acceptable today.
- Downloading ~300 MB of Chrome into the workspace puts binaries in the path of
  any `grep -r .`; that is why the content-hygiene audits run before this step and
  why their greps pass `-I` plus `--exclude-dir=.chrome --exclude="*.zip"`.

## Pandoc fallback plan

If Chrome for Testing downloads fail, the storage.googleapis.com egress is
blocked, or headless rendering becomes flaky, fall back to
`pandoc content/cv/index.md -o public/cv.pdf --pdf-engine=…`.

Accept the trade-off before taking it: Pandoc typesets the **markdown**, not the
page, so typography, layout and styling diverge from what visitors see — and "the
PDF is the page" is the entire reason this artifact exists. The fallback also
loses the `--virtual-time-budget` wait, and needs a PDF engine installed on the
runner. If it ever lands, keep the `pypdf` text audit exactly as it is; only the
renderer should change.

## Evidence

`.github/workflows/hugo.yaml` steps "Install Chrome for Testing (pinned)",
"Render CV PDF from the built site", "PDF text audit — placeholders only";
run `39285257717` (render step green on `0.167.0`).
